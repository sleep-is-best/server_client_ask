# هيكلية لوحة إدارة المشروع (GitHub Project Board) - منصة إسألني (Ask Me)

توضح هذه الوثيقة كيفية تنظيم وإدارة المهام البرمجية لمنصة **إسألني (Ask Me)** التعليمية باستخدام لوحة مشاريع GitHub. نعتمد منهجية **Agile/Kanban** لضمان تدفق العمل (Workflow) بكفاءة وسرعة، مع التركيز على جودة الأدوات التعليمية وأمان البيانات.

## 1. أعمدة اللوحة (Board Columns)

### 📋 قائمة الأفكار (Backlog)
تحتوي هذه القائمة على جميع الميزات المستقبلية، التحسينات المقترحة، والأفكار التي لم يتم تحديد أولوياتها بعد.
- *أمثلة*: دمج الذكاء الاصطناعي لتصحيح الإجابات، تطوير لوحة تحكم للمعلمين، نظام النقاط والمكافآت (Gamification).

### 🎯 المهام القادمة (To Do - Next Sprint)
المهام التي تم اختيارها وتحديد أولوياتها للدورة التطويرية الحالية.
- *أمثلة*: إصلاح محاذاة واجهة المستخدم في "الفصول الافتراضية"، تحسين منطق إعادة اتصال WebRTC أثناء المحاضرات المباشرة.

### 🏃 قيد التنفيذ (In Progress)
المهام التي يعمل عليها المطورون حالياً بشكل نشط.
- *أمثلة*: تنفيذ تبادل مفاتيح RSA لتأمين الجلسات الخاصة، تصميم واجهة رفع الملفات التعليمية.

### 🔍 المراجعة والاختبار (Review / QA)
المهام التي اكتمل كودها البرمجي وتنتظر مراجعة الزملاء (**Peer Code Review**) أو اختبار الجودة (**Quality Assurance**).
- *أمثلة*: اختبار خدمة الخلفية (Background Service) لضمان استقبال إشعارات الدروس، التحقق من سلامة تشفير ملفات PDF المتبادلة.

### ✅ المنجز (Done)
المهام التي تم اختبارها ودمجها (Merged) في الفرع الرئيسي بنجاح.
- *أمثلة*: إعداد اتصال الـ Socket.io الأساسي، تهيئة قاعدة بيانات SQLite المحلية، تطبيق الهوية البصرية (ذهبي، أسود، فضي).

---

## 2. تصنيفات المهام (Issue Labels)
نستخدم التصنيفات الملونة لتسهيل التعرف على نوع المهمة وأولويتها من منظور تعليمي وتقني:
*   **`bug`**: خلل برمجبي يحتاج إلى إصلاح (مثل انقطاع الصوت في المكالمة).
*   **`feature`**: إضافة وظيفة تعليمية جديدة (مثل السبورة التفاعلية).
*   **`security`**: مهام متعلقة بتشفير E2EE وحماية خصوصية الطلاب والمعلمين.
*   **`ui/ux`**: تحسينات بصرية لسهولة الاستخدام التعليمي.
*   **`documentation`**: تحديثات في الوثائق الهندسية أو التعليمات البرمجية.
*   **`high-priority`**: مهام حرجة تؤثر على سير العملية التعليمية.

---

## 3. قواعد الأتمتة (Automation Rules)
لضمان دقة حالة المشروع، نتبع القواعد التالية:
1.  تنتقل المهمة تلقائياً إلى **In Progress** عند ربط فرع (Branch) بها.
2.  تنتقل المهمة إلى **Review** عند فتح طلب سحب (**Pull Request**).
3.  تنتقل المهمة إلى **Done** فور إغلاق الـ PR ودمجه في فرع `develop` بعد اجتياز الاختبارات.

يساعد هذا النظام في توفير رؤية واضحة لتقدم المشروع لجميع أعضاء الفريق وأصحاب المصلحة، مما يضمن تسليم المنصة في المواعيد المحددة وبأعلى معايير الجودة.
